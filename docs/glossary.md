# Glossary

Plain-language definitions for the terms used across this repo's docs.
For deeper explanations of how each concept is used here, follow the
links back into the concept-first docs.

## Agent

A specialized language-model role with a narrow job, described in
natural language, that produces structured output. In this repo, an
agent is a folder under [`/agents`](../agents) containing an
`agent.md` (instructions) and a `manifest.yaml` (runtime metadata).
An agent has no source code of its own; the runtime is either a remote
Foundry assistant or a thin Python wrapper that calls one.

## Remote Foundry Agent

An agent that runs as an assistant on **Azure AI Foundry Agent
Service**. Its instructions and model binding are stored on the
Foundry side. The application reaches it through the `azure-ai-agents`
SDK. This repo's three roles run this way.

## Coordinator

Deterministic application code that sequences the agents, validates
inter-agent messages, enforces timeouts and budgets, and runs at most
one repair pass. Lives in
[`services/api/app/workflows/coordinator.py`](../services/api/app/workflows/coordinator.py).
The coordinator is **not an agent** — it does not talk to a language
model.

## Agent Service

The **Azure AI Foundry Agent Service** capability. It hosts assistants
(remote agents), threads, runs, and messages. This repo invokes it
through [`services/api/app/foundry_agents/sdk_client.py`](../services/api/app/foundry_agents/sdk_client.py).

## Foundry Project

A resource inside Azure AI Foundry that scopes agents, model
deployments, RBAC, and observability for one workload. This repo
provisions exactly one via Terraform.

## Model deployment

A named, region-scoped deployment of a specific model (for example
`gpt-4.1-mini`) inside an Azure AI Services / Foundry account. The
model deployment is what the remote agents run against. In this repo
one deployment is provisioned by Terraform and shared by all three
roles; per-role deployments are supported by the env-var scheme in
`services/api/.env.example`.

## Protocol contract

A versioned JSON Schema that defines the shape of a message crossing
an agent boundary. This repo's contracts live in
[`/contracts/v1`](../contracts/v1) and are enforced by the coordinator
after every agent call.

## JSON Schema

The open specification used to describe the shape of a JSON document.
Files ending in `.schema.json` in this repo are JSON Schemas. The
coordinator loads them at startup and validates every inter-agent
message against them.

## Eval / evaluation

A test that checks how well an agent workflow behaves against a set of
synthetic cases. Evaluations grade the **structure and safety** of the
output (does it use only allowed IDs, does it include the required
human-review caveat), not the exact wording. This repo's synthetic
cases live in [`/evals`](../evals). No automated eval harness is wired
into CI in this repo yet.

## GenAIOps

The operating discipline for generative-AI workloads. Adds
prompt/spec versioning, protocol versioning, safety-oriented
evaluation, and metadata-only observability on top of traditional
DevOps and MLOps. See [genaiops.md](genaiops.md).

## MLOps

The operating discipline for classical machine-learning workloads.
Manages training runs, datasets, model registries, deployments, and
monitoring. This repo does not train a model; the model is served by
Azure AI Foundry. MLOps concerns here reduce to model-version
tracking, retirement handling, and deployment binding.

## DevOps

The operating discipline for software delivery: source control,
automated builds, tests, deployments, and configuration management.
In this repo it shows up as version-controlled Terraform, documented
local commands, and lint/type/test tooling.

## Metadata-only observability

Telemetry that captures only structural information — agent name,
status code, latency, coarse error category, trace ID — and never
captures the user's text, the prompt, or the model's completion.
See [observability.md](observability.md).

## Keyless auth / DefaultAzureCredential

A pattern where the application never holds a static API key.
Instead, `DefaultAzureCredential` from `azure-identity` acquires a
short-lived bearer token for the target resource using the developer's
`az login`, a managed identity, or a workload identity. This repo
uses it in [`services/api/app/foundry_agents/sdk_client.py`](../services/api/app/foundry_agents/sdk_client.py).

## RBAC

Role-Based Access Control. Azure grants callers permission to
resources by assigning roles. This repo grants the app's principal
the `Cognitive Services OpenAI User` role at the AI Services account
scope via Terraform.

## Synthetic data

Data generated by deterministic factories seeded with a fixed constant.
Nothing on screen represents a real person, school, or organization.
Every learner, KPI, and trend value in this repo is synthetic.

## Human review caveat

An explicit statement in every generated recommendation that a human
must review it before use. The Validator Agent enforces the presence
of this caveat as a hard failure. Recommendations that lack it never
leave the coordinator.
